1. **현재 저장소의 기존 파일을 미리 백업**해 주세요 (GitHub 커밋 또는 ZIP).
2. 이 폴더 안 파일 전체를 **해당 학당 GitHub 저장소의 최상위**에 업로드하고 **같은 파일 이름은 교체**하세요. **ZIP 파일 하나만 올리거나 2중 폴더로 올리지 않습니다.**
3. 호스팅(GitHub Pages·Vercel) 자동 배포 완료 후 사이트를 새로고침하세요. 예전 화면이 계속 보이면 브라우저 캐시를 삭제하거나 강력 새로고침하세요.
4. 세 학당에 **각각 별도의 저장소를 사용**합니다. 청도학당 폴더를 송현학당 저장소로 통째로 덮어쓰지 마세요.

## 디자인 변경
- `avatars.js`: 21종 기존 캐릭터 ID·옷장·표정·저장 데이터를 유지하면서 둥근 머리, 점눈, 살구빛 볼, 작은 미소로 통일. 실제 3D 캐릭터는 기존 걷기·의상 체계를 유지합니다.
- `app.js`: 프로필에서 이모지 대신 선택한 캐릭터의 **3D 얼굴 이미지** 표시, WebGL 불가 시 벡터 초상화 대체. 설정의 `소리` 메뉴는 소리 켜기·끄기/음악/자연 소리 선택 화면으로 연결.
- `index.html`: 설정을 요청한 순서대로 재배치, 이모지 메뉴 아이콘을 간결한 SVG 선 그림으로 교체.
- `hakdang-theme.css`, `hakdang-ui.js`: 둥근 고딕 글꼴, 크림색 카드, 설정 UI, 프로필 초상화 렌더링.
- `hakdang-scene.webp`, `hakdang-flowers.svg`, `hakdang-turtle.svg`: 전통 학당/겹산/꽃/생활 시뮬레이션 분위기의 새 배경 및 장식 (3D 이동 UI를 가리지 않도록 입장·설정 중심).
- `favicon.png`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png`: 새 거북이 마스코트로 교체.
- `sound.js`, `letters.js` 등: 설정 소리 동작 및 서체·추가 메뉴 호환성 유지.

## 메뉴 순서
출석 도장 → 기록장 → 오늘의 문장 → 게시판 → 플레이리스트 → **미니게임** → 닉네임, 캐릭터 → 옷장 → 친구부르기 → 소리 → 시점 조절 → 계절, 시간 → 학당 지도 → 이용안내 → 연결 상태

- 기존 **화분 가꾸기**, **편지함**, 게임/친구 기능은 삭제하지 않고 뒤에 배치합니다.
- 기존 친구용 버전에는 **상담 신청 기능·상담 예약 서버가 없으므로**, 동작하지 않는 버튼을 임의로 넣지 않았습니다. 송현학당에는 기존 상담 신청이 그대로 표시됩니다.

## Firebase 설정 / 데이터 보존
- 이번 업데이트는 **화면/3D 캐릭터 자산만 수정**했으므로 **Realtime Database 데이터 구조와 보안 규칙의 변경은 필요하지 않습니다.**
- 만약 기존 Firebase 규칙이 구버전이거나 새 프로젝트라면 포함된 `database.rules.json`은 **세 학당이 공유하는 통합 원본 규칙**입니다. Firebase Console → Realtime Database → 규칙에서 **현재 규칙을 먼저 백업**하고 내용 전체를 검토 후 붙여 넣으세요. 세 ZIP 안의 규칙 파일은 동일합니다.
- GitHub에는 `database.rules.json`을 관리용으로 올릴 수 있지만, **GitHub 업로드만으로 Firebase 규칙이 자동 적용되지는 않습니다.** 콘솔에서 게시해야 합니다.
- `firebase-config.js`에 연결 설정이 포함돼 있습니다. 기존 Firebase 프로젝트를 사용한다면 **프로젝트 ID·databaseURL을 함부로 변경하지 마세요.**
- GitHub/웹 파일만 바꿔도 기존 학생·친구의 서버 기록은 삭제되지 않습니다. 그러나 프로젝트를 바꾸거나 데이터베이스를 지우면 복구가 어려우므로 규칙 게시 전 백업을 권장합니다.

## 보안 주의 (특히 학생용)
- 기존 앱은 **익명 로그인 + 데이터베이스 안의 관리자 문자열**로 관리자 모드를 판정합니다. 이 구조는 엄격한 교직원 전용 권한 인증이 아니며, 클라이언트에서 자기 `members` 항목을 수정할 수 있는 기존 규칙 특성상 권한 우회 위험이 있습니다.
- 민감한 학생 상담 내용은 기존의 별도 Apps Script 상담 예약 환경에서 적절한 접근 통제를 확인해야 하고, Realtime Database에 비공개 상담 내용을 임의로 새로 쌓지 않아야 합니다.
- 실제 학교 서비스로 운영하면서 민감한 정보를 다룰 경우 Firebase Authentication의 검증된 교사 계정과 서버에서 부여한 권한(custom claims 등)으로 변경하는 보안 개편을 별도로 권장합니다. 이번 디자인 수정에서는 기존 학생 데이터·관리 기능을 깨뜨리지 않으려고 규칙을 그대로 유지했습니다.

## 점검
